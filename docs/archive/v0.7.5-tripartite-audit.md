## 1. Operit 真实 finalize 调用顺序

用户消息发送（EnhancedAIService.sendMessage）：

```
prepareConversationHistory            ← history hook + system prompt compose + tool prompt compose
  → dispatchPromptHistoryHooks         (stage=before_prepare_history)
  → SystemPromptConfig（内部再调 compose hooks）
  → tool prompt compose
        ↓
applyPromptFinalizeHooks               ← 第 1 次 finalize
  → dispatchPromptFinalizeHooks        (stage=before_finalize_prompt)
        ↓
applyPromptFinalizeHooks               ← 第 2 次 finalize（同一 context copy，链式传递）
  → dispatchPromptFinalizeHooks        (stage=before_send_to_model)
        ↓
applyFinalizedCurrentUserTurn          ← 尾 USER 特殊处理（替换/追加 finalizedCurrentMessage）
  → mergeAdjacentTurns                 ← 相邻 USER-USER 合并
        ↓
estimatePreparedRequestWindow          ← 宿主 token 估算（publishEstimate=true）
        ↓
serviceForFunction.sendMessage         ← provider 请求（ClaudeProvider.buildSerializedHistory）
```

## 2. 一个真实 Model Hop 包含几个 finalize Hook

| Hop 类型 | finalize 次数 | 说明 |
|---|---|---|
| 用户消息 Hop | **2 次** | before_finalize_prompt + before_send_to_model（同一 fingerprint/cycle） |
| Tool Loop 内部 Hop | **0 次** | processToolResults 直连 `serviceForFunction.sendMessage(currentChatHistory)`，不经过 finalize |

关键结论：**Tool Loop hop 是 ACP 盲区**。插件只能在"用户消息发送"的 2 阶段 finalize
生效；工具循环内无法注入 nudge/preflight。但这也意味着 nudge 不会进入工具循环历史
（ephemeral 天然成立）。

## 3. 最终选择的 nudge carrier 及原因

**选择 SYSTEM turn（preparedHistory 尾部追加）。**

三边审计证据：
- **USER carrier 否决**：`requestHistory` 写回 `execContext.conversationHistory`
  （EnhancedAIService 1110-1111），USER nudge 会泄漏到 Tool Loop 下一 hop 和持久历史；
  且 `mergeAdjacentTurns` 会合并相邻 USER-USER（nudge 与当前消息合并）。
- **SYSTEM carrier 采用**：
  - 模型可见：ClaudeProvider 把 SYSTEM turns 提取为 `systemBlocks`（独立 system 参数，
    随请求发送）；OpenAI/Gemini 同理（system role）。
  - ephemeral：SYSTEM turn 不进入 conversationHistory 写回路径的 USER/ASSISTANT 部分，
    不写 rawTurns、不写 kernelState、不污染 compression block。
  - 不被合并：`mergeAdjacentTurns` 显式排除 SYSTEM。
- 与 billion-context 的差异：原版用 trailing USER carrier（其 proxy 可精确控制
  发送流）；Operit 的 finalize 机制下 SYSTEM 是唯一同时满足可见+ephemeral+不合并的载体。

## 4. nudge 如何保证 ephemeral

1. 当前 Model Hop 可以看到：SYSTEM turn 进 preparedHistory → provider systemBlocks。
2. 下一 Model Hop 默认不会自动继承：插件每 Hop 重新决策注入，不持久化 nudge。
3. 不写入 rawTurns：rawTurnsCache 只存非 nudge 的原始 turns。
4. 不进入 kernelState：nudge 不参与 kernel 的 processTurn/压缩。
5. 不污染 compression block：nudge 是返回视图层追加，不是历史消息。
6. 不改变后续历史 identity：stableKey 只对真实 turns 计算。
7. 不会被 decompress/search_context 当作真实历史：nudge 不在 kernel 消息集。
8. 不会永久进入 Operit chat history：SYSTEM turn 不进 conversationHistory 写回。

## 5. preflight cycle 的真实边界

- **真实 send cycle = 一次用户消息发送**（before_finalize_prompt + before_send_to_model，
  同一 fingerprint）。
- `preflightCycleDone` + `preflightCycleFingerprint` 标识本 send 周期：
  - 同一周期内最多一次 preflight（stage1 触发则 stage2 不再触发）。
  - 下一次真实 send（新 fingerprint）重新 > hard → 可再次 preflight。
- 不会出现：同一次 send 两次 preflight、preflight 被错误 suppress、
  fingerprint 改变误判新 cycle、stateVersion 改变重复 preflight。

## 6. model compression 与 preflight 的区别

| | proactive pressure | model compression | preflight self-heal |
|---|---|---|---|
| 触发 | gentle/strong 阈值 | 模型调用 compress 工具 | 新一轮 send 前 effective > hard |
| 执行者 | 插件注入 nudge | 模型主动 | 插件自动折叠 |
| source | - | model | preflight |
| 时机 | 每 Hop | 模型决定 | 真实 send cycle 开始 |
| 改投影 | 追加 nudge | 折叠历史 | 折叠历史 + rebuild + re-estimate + re-sample |
| 禁止 | - | - | 达到 hard 就普通 Hop 自动 fold（已移除） |

## 7. trace 中如何证明 nudge 真正送达模型

新增 delivery 证明链（nudge-delivery.ts），trace 输出到 acp_trace.jsonl：

```jsonl
{"type":"nudge-delivery","armed":true,"carrier":"SYSTEM","delivered":true,"final":true,"stage":"before_finalize_prompt","level":"gentle"}
```

- `armed`：pressure 决策允许注入
- `carrierSelected`：SYSTEM（审计选定）
- `deliveredToPreparedHistory`：已放入本次返回的 preparedHistory
- `finalPreparedHistoryHasNudge`：stage2 验证 nudge 仍在（宿主可能替换/合并）
- `reason`：final=false 时的原因（如 operit-finalize-replaced）

日志（tools_visibility.log）：
```
[nudge-delivery] stage=before_send_to_model finalHasNudge=1 kind=SYSTEM
[nudge-delivery] stage=before_finalize_prompt armed=1 carrier=SYSTEM delivered=1 final=1 reason=-
```
