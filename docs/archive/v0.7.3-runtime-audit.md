## 1. Hook 顺序（代码 + 运行日志交叉确认）

宿主实际调用链（以 `logs/tools_visibility.log` 08:55:35~08:55:46 实测为准）：

```
SystemPromptCompose: after_compose_system_prompt  (sysLen 14520 -> 15948, 注入 ACP 指南)
        ↓
PromptFinalizeHook:  stage=before_finalize_prompt (count=2233, 含 SYSTEM+SUMMARY)
        ↓
PromptFinalizeHook:  stage=before_send_to_model   (count=239, 投影后视图)
        ↓
Send to model
```

| Hook | 输入 turns 来源 | 可改 preparedHistory | 会调 ACP project() | 重算 token | 改 systemPrompt | 改 availableTools | 宿主用哪个结果 |
|---|---|---|---|---|---|---|---|
| **onSystemPromptCompose** | 宿主 compose 的各段 | 否（只 systemPrompt） | 否 | 否 | ✅（after 阶段注入 ACP 指南，实测 1428 字符生效） | 否 | systemPrompt |
| **onEstimateHistory** | chatHistory | ✅ | ✅（estimate() 只读） | ✅ | 否 | 否 | 估算计数（advisory only） |
| **onEstimateFinalize** | preparedHistory | ✅ | ✅（estimate() 只读） | ✅ | 否 | 否 | 估算计数（advisory only） |
| **onFinalize** (before_finalize_prompt) | 消息库原始历史 | ✅ | ✅（project() 全量） | ✅ | ✅（appendAcpSystemPrompt） | 否 | **权威投影①** |
| **onFinalize** (before_send_to_model) | 宿主基于①整理 | ✅ | ✅（project() stage2 cache） | ✅ | 否（复用①的 SYSTEM） | 否 | **权威投影②（最终发送）** |
| **onToolPromptCompose** | availableTools | ✅（只 tools） | 否 | 否 | 否 | ✅（注入 ACP 4 工具） | availableTools |

**结论（文档第七节情况判定）**：
- estimate hook = **advisory only**（宿主估算右上角计数/阈值判断用，不参与最终发送）。
- send hook（before_send_to_model）= **authoritative**（最终发给模型的 preparedHistory）。
- 两者投影同源（同一 kernel state / 同款折叠），唯一允许差异：estimate 无 nudge、无 ephemeral 诊断。

## 2. 每个 Model Hop 是否经过 pressure

**V0.7.3 改造前**：3 个分支绕过（stage2 cache、fingerprint cache hit、incremental path 全部直接 return，无 pressure）。

**V0.7.3 改造后（代码已修复）**：

| 路径 | pressure 执行 | ledger 记录 | nudge 注入 |
|---|---|---|---|
| full projection | ✅（collectAndEvaluatePressure） | ✅ | ✅（buildNudgeText） |
| incremental | ✅（改造后先 pressure 再 return） | ✅ | ✅（buildNudgeTextFromReason） |
| fingerprint cache hit | ✅（改造后先 pressure 再 return） | ✅ | ✅（buildNudgeTextFromReason） |
| stage2 before_send | ✅（改造后先 pressure 再 return） | ✅ | ✅（buildNudgeTextFromReason） |

**统一结构（文档第四节）**：
```
prepareHop → collectUsage(host sampling + estimate) → evaluatePressure
  → selectProjectionPath(full/incremental/cache)
  → injectNudge(nudge 必入 preparedHistory) → finalizeProjection
```

**禁止项已消灭**：
- ❌ incremental → return → skip pressure（已改造）
- ❌ cache hit → return cached projection → skip pressure（已改造）
- ❌ stage2 复用缓存 → nudge 丢失（已改造：stage2 重新 pressure 决策 + 注入）

## 3. 最终发送上下文唯一性

- **before_send_to_model** 返回的 preparedHistory = ACP 最终投影（SYSTEM 含 ACP 指南 + nudge 若决策注入）。
- 宿主在此 hook 后不再修改 preparedHistory（日志实证：before_send_to_model 后无其他 hook 改 history）。
- **唯一后续变换**：宿主将 SYSTEM turn 内容喂给 model，ACP 指南已在 SYSTEM 内（sysHasAcp=true 实测）。

## 4. Nudge 实际可见性

```
pressure.allowInject=true
  → nudgeInjected=true（SYSTEM 消息 push 进 preparedHistory）
  → preparedHistory contains nudge（full path buildNudgeText / 其余路径 buildNudgeTextFromReason）
  → before_send_to_model 返回（stage2 重新决策，nudge 不因缓存丢失）
  → Model receives（SYSTEM 内容包含 [ACP 上下文管理] 指南 + nudge 提示）
```

## 5. Token ledger（真实 Hop 样例结构）

hop ledger 持久化在 `usageState.hopLedger`（最近 40 条），每条：

```
{ hop, estimateTokens, actualTokens, hostTokens, compressionCredit,
  effectiveTokens, source, confidence, at }
```

- `actualTokens` 保持 undefined（宿主无 provider usage 回调，诚实语义）。
- source ∈ estimate | host | hybrid（host DB 有值时）。
- 一条 ledger = 一次真实 Model Hop 的发送前 pressure snapshot（四路径全覆盖）。
