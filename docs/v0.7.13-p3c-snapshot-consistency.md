## 七、ROOT CAUSE

**STAGE2 / CACHE-HIT / INCREMENTAL 三条路径把 `cached.kernelState`（上一次持久化 V1）
当作 next state 写回，覆盖了 FULL path 刚产生的 V2**。V2 的 refs（m00125..m00240）
只活在 nudge 文案与内存 turn 里，从未持久化。

## 八、附带发现：工具 mutation 与 project 锁不互斥

```
compress/absorb/decompress（acp_tools）→ applyCompression 等 → 直接 persistence.save
project（FULL/STAGE2）→ acquireLock(sessionKey)
```

两者**没有共用同一把锁**。工具 mutation（V2 → V3）后，若 project 缓存未失效，
STAGE2 仍可能用 V1 覆盖（文档第十四节风险）。

## 十、修复方向（P3-D 最小修复候选，待用户确认）

**候选 1（最符合 invariant）**：非-FULL 路径保存时，若 FULL path 已产生新
`turn.state`，应保存 FULL 的 V2（而非 cached V1）。即：把 V2 从 FULL path 的
返回值/内存传递到 STAGE2/CACHE-HIT/INCREMENTAL，作为 authoritative kernel snapshot。

**候选 2（stateVersion 递增）**：FULL path 产生新 state 时 `stateVersion+1`，
STAGE2/CACHE-HIT 用旧 stateVersion 判断缓存失效，避免用旧 state 覆盖。

**候选 3（锁统一）**：compress/absorb/decompress 与 project 共用 acquireLock，
防止工具 mutation 与投影写回竞争。

**原则**：候选 1 + 2 联合（V2 作为唯一权威 + stateVersion 递增），候选 3 作为
附带的健壮性修复。**未写任何代码**，等待进入 P3-D。
