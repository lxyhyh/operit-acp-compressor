# V0.7.4 — Preflight Over-Hard：新一轮发送前的安全自愈触发条件
日期：2026-09-08
范围：operit-acp-compressor V0.7.4（基于 V0.7.3 fdedc94）
---

## 1. 目标纠正（用户需求原文语义）

本版本**不是**"首次 Model Hop 主动压缩"，也**不是**"每轮开始都主动压缩"。

真正目标：
```
上一轮对话结束 → 历史继续保留 → 新一轮开始
  → 采样当前 host/effective context
  → 如果已经 > hard limit
    → 先主动执行一次 preflight compression
    → compression success → 重新 projection → 重新计算 pressure
    → 再发送本轮 Model Hop
如果没有超过 hard limit：
  → 正常走现有 gentle / strong pressure 管理
  → 不做额外 preflight compression
```

**Hard Limit 新语义**：
> "进入新的发送轮次时，如果当前上下文已经越过安全边界，则必须先做一次
> preflight compression，避免把明显超窗的历史直接交给模型。"

Hard limit **不再是**"任意一个 Hop 一超过 hardLimitPct 就立即 emergency fold"。

## 2. 四种压缩动作明确区分

| 动作 | 触发条件 | 行为 | 统计字段 |
|---|---|---|---|
| `pressure-gentle` | usage ≥ gentleThresholdPct (0.72) | nudge 提示模型准备压缩 | gentleNudges |
| `pressure-strong` | usage ≥ strongThresholdPct (0.82) | nudge 提示模型立即压缩 | strongNudges |
| `preflight-over-hard` | **新一轮发送前** effectiveTokens > hardLimitTokens (0.85) | 插件主动折叠（自愈），压缩后重建投影 | preflightTriggered/preflightSucceeded |
| `safety-emergency` | preflight 失败 / 压缩后仍超 / 本周期已 preflight 仍超 | 最终兜底（emergency nudge） | safetyEmergencyTriggered/emergencyTriggered |

## 4. Preflight 触发点（真实发送边界）

Hook 调用顺序（宿主真实调用链）：
```
SystemPromptCompose: after_compose_system_prompt
  ↓
PromptFinalizeHook:  stage=before_finalize_prompt   ← full path（preflight 触发点 ①）
  ↓
PromptFinalizeHook:  stage=before_send_to_model     ← stage2 path（preflight 触发点 ②）
  ↓
Send to model（真正发送边界）
```

| 路径 | preflight 触发点 | preflightDoneForCycle |
|---|---|---|
| **full**（before_finalize_prompt） | `checkAndRunPreflight` 在 processTurn 后、collectAndEvaluatePressure 前 | false（stage1 首次） |
| **incremental** | 增量投影后、返回前 | `cached.preflightCycleDone && fingerprint 匹配` |
| **cache hit** | 复用缓存投影后、返回前 | 同上 |
| **stage2**（before_send_to_model） | 复用 stage1 投影后、返回前 | 同上（stage1 已 preflight 则 true） |

## 5. Compression 前后 usage 重算路径（需求 7）

```
preflight 判定（采样 host + estimate → effective）
  → effective > hardLimitTokens?
    → runPreflight（最多 3 轮，每轮压 2 段最旧）
    → rebuild projection（turn2 = processTurn 压缩后状态）
    → 重新估算 tokenEstimate（collectCoveredMessageIds + estimateProjectionTokens）
    → collectAndEvaluatePressure 用【压缩后 sendEstimate】重新采样 host + 重算
      effectiveTokens / pressurePct / source
    → 最终 preparedHistory（压缩后视图）
```

绝不复用压缩前的 `tokenEstimate / effectiveTokens / pressurePct / hard-limit 状态`。

## 6. 与普通 pressure compression 的区别

| 维度 | pressure-gentle/strong | preflight-over-hard |
|---|---|---|
| 谁执行 | 模型（收到 nudge 后调用 compress 工具） | 插件（Adapter 主动折叠，不等模型） |
| 触发时机 | 每 Hop 持续 pressure 评估 | 新一轮发送前（超 hard 边界） |
| 是否修改 preparedHistory | 追加 nudge SYSTEM 消息 | 折叠旧历史 → 投影变短 |
| 失败兜底 | 无（下轮继续 nudge） | preflight 失败 → safety-emergency |
| credit 发放 | 模型 compress 后 | preflight 折叠后同样发放 |

## 7. Emergency 最终触发条件（需求 4/5/12）

`emergency`（safety-emergency）**只**在以下情况触发：
1. preflight 压缩后**仍** > hard limit（`preflightDoneForCycle=true` 后再超）；
2. preflight 执行失败（无可压缩范围 / applyCompression 抛错）；
3. 本 send 周期已 preflight，同一周期再次超限（不重复压缩 → 兜底）。

**禁止**：
- 普通 Hop 一超过 hardLimitPct 就 emergency fold（V0.7.3 及以前的旧逻辑已移除）；
- 每轮固定主动压缩（未超 hard 不 preflight）；
- 同一轮内无限 compression loop（preflightCycleDone 限制一次）。

## 8. Trace / Ledger 区分（需求 10）

Trace 新增：
- `type: "preflight", level: "preflight-over-hard"`（自愈折叠成功）
- `type: "emergency", level: "safety-emergency"`（最终兜底）
- project trace 的 `preflight: { rounds, freed, stillOverHard, context, hard }` 字段

Ledger（usageState.hopLedger）继续逐 Hop 记录 estimate/actual/host/effective，
preflight 折叠后下一个 Hop 的 effective 会反映压缩后低位（因为 tokenEstimate 已重算）。

## 10. 真实/模拟 Trace（195K → 215K → preflight → 90K → 继续运行）

```
Hop N-1 结束：effective = 195K（host=195K, estimate=198K, hard=170K @ 85%×200K）
   → 未超 hard → 正常 pressure（78% → gentle nudge）

── 新一轮开始 ──
Hop N（新一轮发送前）：
  → 采样 host = 215K（上一轮结束后又累积了 20K）
  → effective = max(host=215K, estimate=212K) = 215K
  → evaluatePreflight: 215K > 170K hard → action=preflight-over-hard
  → runPreflight: 压最旧 2 段（[ACP 自动折叠] 摘要）
  → 压缩后 rebuild projection → re-estimate
  → post-estimate = 90K（压缩释放 125K）
  → collectAndEvaluatePressure 用 sendEstimate=90K 重新采样
  → pressurePct = 45%（回到安全区）→ 无 nudge
  → 发送本轮 Model Hop（90K 投影）

── 下一轮继续 ──
Hop N+1：从 90K 继续增长 → 后续可再次 gentle/strong → 可再次 compression
  （preflight 关闭了当前 epoch，新 epoch 正常开启）
```

Trace 记录示例：
```jsonl
{"type":"project","detail":{"hop":41,"effective":215000,"effPct":108,"preflight":{"rounds":1,"freed":125000,"stillOverHard":false,"context":215000,"hard":170000}}}
{"type":"preflight","level":"preflight-over-hard","detail":{"blocks":2,"tokens":125000,"rounds":1,"stillOverHard":false}}
{"type":"project","detail":{"hop":41,"effective":90000,"effPct":45,"preflight":null}}
```
