## 6. ROOT CAUSE CLASSIFICATION

### 两个问题严格分开（文档要求的核心）

**问题 1：工具是否进入了错误 session？**
- 是（间歇性）：20:45-20:51 注入 f23f6048（0 blocks 空会话）
- 21:03 后已恢复 d2572685。当前 state 正确。
- **影响**：当时窗口内的 compress/acp_status 调用全部查空会话失败。

**问题 2：进入正确 session 后，ref pool 是否随 4319 raw turns 增长？**
- **否**。ref pool 停在 3297（m03297），raw 已 4319。
- 但 **kernel 本身会增长**（实验：stableKey 映射 → 5383；identity 映射 → 7616）
- **Adapter 层未把增长结果持久化成功**。

### 根因分类

```
主根因 = COMBINED（REF_NAMESPACE + MESSAGE_SNAPSHOT + SESSION 间歇错配）
```

| 候选 | 判定 | 证据 |
|---|---|---|
| REF_NAMESPACE | ✅ 确认为主因之一 | 宿主 nudge m05709..m06088 vs ACP m00001..m03297；所有 session 无 m05709 |
| REF_GROWTH | ✅ 确认为主因之一 | raw 4319 > ref 3297，idx2233 后 2072 条无 ref；kernel 会增长但 adapter 未持久化 |
| MESSAGE_SNAPSHOT | ✅ 确认 | 持久化 state 用 stableKey 格式；identity 映射 processTurn 导致 blocks 全失活 |
| STATE | ⚠️ 次级 | stateVersion=4 但 kernelState 长期未变；hostMetadata 持续更新（拼装状态） |
| REGISTRATION | ❌ 排除 | compress/acp_status 已被宿主调用（tool_params.log 实证） |
| SESSION | ⚠️ 间歇 | 20:45-20:51 错注入 f23f6048；21:03 后正确 |

### 最终链路（第一个分叉节点）

```
NUDGE TARGET (m05709..m06088, 宿主视图)
  ↓ HOST vs ACP REF NAMESPACE 不一致 ← 第一个分叉点（REF_NAMESPACE）
TOOL CALL compress(m05709..m06088)
  ↓ SESSION 间歇错配（f23f6048 窗口）← 第二分叉点（SESSION WRONG）
  ↓ 即使 session 正确，ref 仍无法锚定
STATE（kernelState 停在 m03297，ref 未随 4319 turns 增长）
  ↓ MESSAGE_SNAPSHOT（stableKey vs identity 格式断裂）
  ↓ REF RESOLUTION（m05709 MISS）
COMPRESSION（失败；用正确 namespace ref 则成功）
```

### 部署版本确认

- 宿主实际加载：`toolpkg_cache/com.operit.acp_compressor-6c47f2fe/dist/main.js`
- 与工作区 dist md5 **一致**（72c4e470...）
- 含 V0.7.9 identity bridge（mapTurnsWithIdentity / identityBridge 写入点）
- **但持久化 state 的 kernelState 是 V0.7.8 之前的 stableKey 格式**
  → 新版 dist 的 identity 映射 processTurn 从未成功持久化
  （若持久化则 blocks 全失活，等于丢失全部压缩成果）

### 为什么 ref 停在 3297？

- b45 最后创建于 09-08 14:18（UTC 22:18），ref 到 m03297
- 之后 raw 增长到 4319，但每次 full processTurn 用 identity 映射
  → blocks 失活 → 保存这样的 state 会摧毁压缩成果
  → **adapter 实际保存的仍是旧 kernelState（可能 cache-hit/stage2 路径），
  或 processTurn 结果因 identity/state 不匹配被丢弃**
- hostMetadata（usageState/acpNudge/runtimeStats）持续由 stage2/cache 路径更新
  → state 文件 mtime 在变，但 kernelState 部分冻结在 b45/m03297

## 7. 下一步建议（不实现，仅方向）

1. **修复 namespace 断裂是最高优先级**：
   - 要么让 nudge 的 ref 与 ACP session ref 同源（宿主 nudge 用 ACP 的 ref）
   - 要么提供「宿主 ref → ACP ref」的 bridge 映射
2. **修复 identity/state 格式断裂**：
   - identity 映射与持久化 state 的 blocks/messageRefs 格式必须一致
   - 迁移旧 state 或让 identity 映射兼容 stableKey 格式
3. **修复 ref 增长持久化**：
   - full processTurn 的新 ref 必须真正落盘（当前被格式断裂卡住）
4. **SESSION 注入**：宿主固定注入 nudge 所属会话（或工具层严格校验
   `__operit_package_chat_id` 与 nudge 会话一致性，不一致时拒绝而非猜测）
