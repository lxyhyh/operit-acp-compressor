## C. 压缩消息是否成为下一轮历史

**否（结论 2）**：
- `requestHistory` 只用于本次 `calculateInputTokens` 和本次发送
- 宿主 DB 仍存原始 ChatMessage（ChatHistoryManager.persistMessageLocked L665-687：`messageDao.insertMessage` 原始内容）
- 下一轮：从 DB 读原始 → ACP 重新投影 → 上下文再次膨胀
- **ACP 压缩成果不持久**

## D. currentWindowSize 是否需要 ACP 修改

**不需要**。宿主已用 Hook 后 preparedHistory 计算（B 证明）。ACP 不该直接写 currentWindowSize。

  DB 存原始消息 → 下一轮读原始 → 重复投影开销 + 上下文无法根治
