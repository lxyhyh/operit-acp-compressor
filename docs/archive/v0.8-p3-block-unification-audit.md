## 1. 0.7.5 前自动折叠的真实实现（源码取证）

- bc-upstream `src/preflight.ts`：`preflightCompress()` 在发送前做 fit check，
  把超窗内容分块（splitChunks），**逐块调 summarize（LLM）生成摘要**，
  最终同样走 `core.applyCompression()` 建块。
- Operit 移植版（V0.7.4/V0.7.5 preflight 方案 A）：同构——
  isNoiseText 噪音剔除 + buildDeterministicSummary 确定性抽取（沙箱无 LLM），
  同样经 `core.applyCompression()` 建块。
- **结论：旧自动折叠从未有"第二种 block"，只是 summary 来源不同
  （LLM vs 确定性抽取），建块一律走 kernel。**

## 2. 当前主动 compress 的真实实现

`adapter.ts applyCompression(sessionKey, ranges, messages, chatId)`（L1176-1284）：
1. mapTurnsWithIdentity(rawTurns) → mapping.messages
2. `core.applyCompression({ranges, messages, state: loaded.kernelState, config})`
   → kernel 权威创建 block（结构/refs/effectiveMessageIds/state mutation）
3. stateVersion++、lastProjectionFingerprint 置空、缓存失效
4. blockSources 标记 `"model"`、stats.compressCalled/++、credit 窗口
5. persistence.save

## 3. 两者为什么"看起来"不同 / 实际差异点

| 维度 | 模型 compress | V0.8-P2 emergency fold | 判定 |
|---|---|---|---|
| kernel 入口 | core.applyCompression | **core.applyCompression（同款）** | ✅ 一致 |
| block 结构/refs/coveredIds | kernel 创建 | **kernel 创建（同款）** | ✅ 一致 |
| state/persistence | save+version++ | save+version++（FULL path 共用） | ✅ 一致 |
| projection | 下次 project() 折叠 | 当场 processTurn 重投影 | ✅ 等价（更及时） |
| summary 来源 | 模型文本 | buildDeterministicSummary 抽取 | ⚠️ 不同（规则 3 允许） |
| blockSources 标记 | `"model"` | **缺失（未标记）** | ❌ P2 缺陷 |
| stats | compressCalled/modelSaved | emergencyTriggered/emergencySaved | ✅ 分入口计数（并存） |

## 4. P2 哪些正确、哪些错误

**正确**：
- 复用 core.applyCompression 唯一入口（未发明 EmergencyBlock/第二套 block）
- 触发时机符合任务书三：请求装配 + pressure 检查之后
- 保护区（最近 8 条）排除；已覆盖段不重复建块（covered 集合过滤）
- 失败 → 保留原始历史落回 cap（cap 此时是最终安全保护阶段，合规）

**错误（已修）**：
- emergency 块未写 blockSources —— 无法区分块来源（本次修复：标 `"auto"`）

## 5. 统一后的 Block 创建路径

```
模型 compress 工具 ─┐
                    ├─→ [统一入口] core.applyCompression（kernel 权威建块）
自动折叠 forced ────┘         │
                              ├─ summary 生成入口可不同（model 文本 / 确定性抽取）
                              └─ block 契约、refs、stateVersion、持久化、projection 完全一致
```

不存在 AutoFoldBlock/CompressBlock/EmergencyBlock 并行实现。

## 6. 自动折叠的真实触发时机与入口

- 时机：project() 发送链路，历史装配（mapping）+ pressure 评估之后、cap 之前
- 条件：`pressure.level === "forced"` 且 effective > 目标（gentle 阈值 70%）
- 入口：直接调 core.applyCompression（与模型 compress 同一函数）
- 失败回退：不写不完整 block，落回 cap（最终安全阶段）
