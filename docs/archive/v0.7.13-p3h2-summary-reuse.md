结论 A：Operit 原生总结机制可以直接复用

## 一、总结边界 = sender=="summary" 的 ChatMessage

`AIMessageManager.getMemoryFromMessages`（L702-715）：
```kotlin
val lastSummaryIndex = messages.indexOfLast { it.sender == "summary" }
val relevantMessages = if (lastSummaryIndex != -1) {
    messages.subList(lastSummaryIndex, messages.size)  // 只取 summary + 新消息
} else {
    messages
}
```

- 旧消息保留 DB，**永不发送给模型** ✅
- 无需删除旧消息、无需改 currentWindowSize

## 二、官方写入接口（两层）

| 层 | 方法 | 位置 |
|---|---|---|
| DB 层 | `ChatHistoryManager.addSummaryMessageBetweenSliceNeighbors(chatId, message, beforeTs, afterTs)` | ChatHistoryManager.kt L814 |
| DB 层 | `ChatHistoryManager.addMessage(chatId, message)` | ChatHistoryManager.kt L835 |
| UI 层 | `ChatHistoryDelegate.addSummaryMessage(summaryMessage, beforeTs, afterTs, chatIdOverride)` | ChatHistoryDelegate.kt L1573 |

`addSummaryMessageBetweenSliceNeighbors` 内部：查 before/after 锚点 → 防相邻 summary 重复 → `persistMessageLocked` 写 DB。

## 三、触发机制

`summarizeMemory`（AIMessageManager L646）：
- token 阈值（`usageRatio >= tokenUsageThreshold`）
- 消息数阈值（`enableSummaryByMessageCount`）
- 生成 summary → `sender="summary"` 消息写 DB

## 四、ACP 复用方案

```
ACP compress 建块
  → 生成 block 摘要文本
  → 调宿主 addSummaryMessageBetweenSliceNeighbors 写入 sender="summary" 消息
  → 后续 getMemoryFromMessages 自动只发 summary + 新消息
```

- 不需要：删除旧消息 / 修改 currentWindowSize / 自己替换 DB
- 唯一障碍：插件 JS 侧能否调用 ChatHistoryManager（Kotlin 单例）——需确认宿主是否已对 ToolPkg 暴露，或加最小桥接
