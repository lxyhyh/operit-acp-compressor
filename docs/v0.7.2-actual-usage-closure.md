# V0.7.2 Actual Usage Closure — Audit & 实施记录

日期：2026-09-08

## 1. recordUpstreamUsage() 真实调用链追踪

### 结论：生产链路中它**从未被调用**。

证据（全仓库 grep，`src/` 唯一命中是定义本身）：
- `recordUpstreamUsage` 在 `src/` 下只有 `src/acp/usage.ts` 里的**定义**与注释引用。
- 唯一**调用点**是 `tests/pressure.test.mts:285`（测试自测），生产代码 0 调用。
- 同理 `consumeCompressionCredit` 也只在测试中调用（生产未接线）。

### 为什么收不到真实 usage——Operit ToolPkg 能力边界

调查宿主 `skills/Sandbox/*.d.ts` 确认 Operit ToolPkg 沙箱**不暴露**任何 provider 级 usage 回调：

| 候选接口 | 能力 | 是否可用 |
|---|---|---|
| `AiProviderSendMessageResult.usage` | AI Provider **注册方**的返回类型 | ❌ 我们是 ToolPkg 插件，不是 provider 注册方 |
| `calculateInputTokens` | `registerAiProvider` 的 handler 参数 | ❌ 同上，只对 provider 注册方可用 |
| `PromptFinalizeHookEvent.payload.systemPrompt` | 宿主发送前上下文 | ⚠️ 有（我们已在 onFinalize 里读）但**不含 usage**（那是 provider 计费后才知道的） |
| `ToolLifecycleHook` | 工具执行前后 | ⚠️ 宿主 **IllegalStateException 不支持**（V0.6 已回退） |
| `chat.currentWindowSize`（宿主 DB） | 宿主自己维护的上下文窗口估算 | ✅ **唯一可用**（`host-usage-adapter.ts` 已在读） |

### 实际可接入位置（未来宿主开放时）

1. **宿主暴露 `onMessageResult(usage)` hook**（最理想）：在 `main.ts` 注册，收到 `usage` 即 `usageManager.recordUpstreamUsage({ contextTokens: normalizeUsage(...).contextTokens })`。
2. **宿主在 finalize payload 增加 usage 字段**：`onFinalize` 里直接读。
3. **宿主增加 AiProvider 回调到 ToolPkg**：`main.ts` 里挂 provider 代理，转发 usage。
4. 当前降级路径：**host DB `chats.currentWindowSize`** 作为中可信度（medium）的宿主测量，已经是插件实际能拿到的最接近真实值。

### 三源优先级（实际生效）

```
estimate（low，发送前自算）  ← 每 hop 都有
host（medium，DB currentWindowSize） ← 每 hop 尽力读
actual（high，provider usage） ← 目前永远 undefined（无回调），未来 hook 就绪后接入
effective = max(estimate, host, actual - credit)
```

## 2. 实施变更清单

### usage.ts（重写）
- `recordUpstreamUsage`：**Actual 唯一入口**；net accounting（credit 只按「usage 超出折叠窗口」部分消费）；到达时自动记一条 ledger。
- `recordEstimate` / `recordHostUsage`：每 hop 记 `lastEstimateTokens`/`lastHostTokens` + hop 号。
- `consumeCompressionCredit(actual, foldedWindow)`：明确 net 语义（旧版无条件清零已废）。
- `recordHopEntry`：pressure 决策视图（发送前）逐 hop 记录。
- `hopLedger`：最近 40 条随 `usageState` 持久化。

### adapter.ts
- `applyCompression(sessionKey, ranges, messages, chatId?)`：**显式 chatId 参数**。
- 删除 `sessionKey.split("_")[0]` 推导（主对话 sessionKey=chatId 本身，split 无意义；子任务错误）。
- chatId 解析顺序：`显式参数 chatId > hostMetadata.lastChatId > 无`。
- `project()`：每 hop 记录 `lastChatId`（真实 hook 传入）+ `recordHopEntry` ledger + trace 加 `hop`。
- trace detail 增加 `hop` 字段。

### persistence.ts
- `usageState.hopLedger`：逐 hop 持久化。
- `hostMetadata.lastChatId`：真实 chatId 持久化。

### acp_tools.ts
- compress 工具：显式传递 `chatId`（从 `injectedChatId(params)` 或 `params.chatId` 取）。
